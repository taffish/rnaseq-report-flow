# RNA-seq Primer and Report Interpretation Guide

This document accompanies reports generated by `taf-rnaseq-report-flow`. It is both a report interpretation guide and a compact RNA-seq primer for new users. It does not write project-specific conclusions for the user. Instead, it explains what biological question each step answers, how common plots should be read, which statistical ideas matter, and which conclusions cannot be made automatically by a report.

## 1. What RNA-seq Can Answer

Bulk RNA-seq measures RNA abundance from a population of cells or tissue. It does not directly measure protein activity, metabolic flux, or causal mechanism, but it can answer a chain of expression-level questions:

- Are the reads reliable enough for downstream analysis?
- Can reads be assigned consistently to transcripts, genes, or genome positions?
- Are samples comparable, and are biological replicates consistent?
- Under the selected design and contrast, which genes changed?
- Do changed genes point to coherent functions, pathways, or biological processes?
- Which results are useful as hypotheses for follow-up validation?

The report should be read as an evidence chain from sequencing observations to biological hypotheses:

```text
FASTQ reads
-> QC / trimming
-> transcript or gene quantification
-> count matrix / TPM matrix
-> sample relationship and normalization checks
-> differential expression
-> enrichment
-> biological hypotheses and reusable evidence
```

Each report section should be interpreted within this chain.

## 2. Recommended Reading Order

1. Start with the project overview

   Confirm sample count, route, collected modules, plot count, linked HTML reports, and whether DE and enrichment outputs are present. This tells you whether the report covers the analysis path you expected.

2. Check quality before biology

   Do not jump straight to DE genes and enriched terms. Review read quality, quantification completeness, sample relationships, mapping/count evidence, and expression distributions first. If samples or distributions look suspicious, DE and enrichment should be interpreted cautiously.

3. Read differential expression next

   Differential expression asks: under the selected design and contrast, which genes have statistical evidence for expression change? It is a prioritization layer for candidate genes and follow-up interpretation, not causal proof.

4. Read functional enrichment last

   Enrichment organizes gene-level signals into gene-set or biological-process hypotheses. It depends on the gene ID space, background universe, gene-set source, and threshold choices.

## 3. Experimental Design Basics

### Biological Replicate

A biological replicate is an independent biological sample from the same condition. Replicates estimate natural biological variability and are essential for differential expression. DE is not just a comparison of two numbers; it compares between-condition signal against within-condition variability.

### Technical Replicate

A technical replicate is repeated library preparation, sequencing, or processing from the same biological material. It helps evaluate technical noise, but it is not a substitute for biological replication. Treating technical replicates as biological replicates inflates sample size and overstates confidence.

### Condition

A condition is the biological state being compared, such as WT, KO, control, treated, tissue, or time point. Condition labels in the sample table must match the real experimental design.

### Batch

A batch is a technical grouping such as library preparation date, sequencing lane, operator, center, or reagent lot. If batch is perfectly confounded with condition, the model cannot cleanly separate technical and biological effects.

### Contrast

A contrast is the exact comparison requested from the model, such as `treated vs control` or `KO vs WT`. A dataset can support multiple contrasts, but each contrast must correspond to a clear biological question.

### What If There Is Only One Condition?

If a dataset contains only three WT samples and no treatment or control comparison, it can still support:

- read QC;
- trimming;
- Salmon/Kallisto expression quantification;
- gene/transcript count matrix;
- TPM matrix;
- sample correlation;
- expression distribution;
- optional alignment/count/QC branch.

It cannot support condition-level differential expression, and it cannot support standard ORA based on a DE gene list. It can still deliver expression matrices, expression-profile summaries, sample-quality checks, or a foundation for adding comparator samples later.

## 4. Module Questions

### Reference Preparation

This module asks whether the genome, annotation, transcripts, `tx2gene`, and indexes are ready for downstream analysis.

Check whether:

- genome and annotation come from the same release;
- transcript IDs and gene IDs map consistently;
- Salmon/Kallisto indexes support expression quantification;
- HISAT2 indexes support the optional genome-aware alignment branch.

If reference sequences and annotation IDs are inconsistent, quantification, counting, DE, and enrichment can all become difficult to interpret.

### Read QC and Expression Quantification

This module asks whether reads are usable and expression estimates are complete.

Main evidence includes FastQC/MultiQC, fastp, Salmon/Kallisto summaries, and gene/transcript count or TPM matrices. Common checks include read depth, quality profiles, adapter/low-quality trimming, and whether all expected samples were quantified.

### Alignment, Counting, and RNA-seq QC

This optional genome-aware evidence branch asks whether the reads are compatible with the genome/annotation and whether featureCounts and BAM-level QC support the expression route.

Main evidence includes HISAT2 summaries, BAM file indexes, featureCounts assignment, RSeQC, and Qualimap reports. It is useful for mapping rate, gene body coverage, library quality, annotation compatibility, and count-based evidence.

### Differential Expression

This module asks which genes changed under the selected model and contrast.

Main evidence includes DESeq2 result tables, PCA, sample correlation heatmap, expression distributions, MA plot, volcano plot, DEG count barplot, heatmap, and top-gene expression plot.

Read the figures in two groups:

- model and sample checks: PCA, sample correlation, expression distribution, normalized count distribution;
- contrast signal: volcano, MA, DEG counts, heatmap, top-gene expression.

### Functional Enrichment

This module asks whether changed genes or ranked gene evidence point to specific biological processes, pathways, or gene sets.

ORA starts from a significant-gene list and asks whether selected gene sets contain more hits than expected. GSEA starts from the full ranked gene list and asks whether gene-set members accumulate at one end of the ranking. ORA is sensitive to the significance threshold and background universe. GSEA is sensitive to the ranking statistic and gene-set definition.

## 5. Deep-Dive Modules: How Biology Becomes Technical Evidence

### Reference: Biology Becomes Coordinates

Reference preparation defines the vocabulary of the entire RNA-seq analysis. The genome FASTA provides coordinate space. GFF/GTF annotation defines genes, transcripts, exons, and parent-child relationships. Transcript FASTA and `tx2gene` tables connect transcript-level evidence back to gene-level interpretation. Counts, TPM values, DE results, and enrichment results all depend on this vocabulary.

Biologically, a gene symbol, systematic ID, transcript ID, and genomic locus are related but not interchangeable. When a report says that a gene changed, the evidence may have passed through several mappings: reads to transcripts, transcripts to genes, genes to gene sets. If any mapping layer is wrong, the final interpretation can point to the wrong biological object.

Technically, the key checks are release consistency, sequence-name consistency, complete `gene_id` and `transcript_id` attributes, broad `tx2gene` coverage, and whether Salmon/Kallisto and optional HISAT2 indexes were built from the same reference package. Reference preparation is therefore not just file preparation. It defines the boundary of every downstream biological claim.

Common risks include genome/annotation release mismatch, chromosome naming differences, missing stable gene IDs, failed transcript extraction, mixed gene symbol and systematic ID spaces, and enrichment backgrounds that do not match the expression matrix. A pipeline can still run under these conditions, but its biological meaning becomes fragile.

### FASTQ QC: Observations Before Conclusions

FASTQ is the raw observation layer. Each read is a sampled RNA/cDNA fragment plus base-level uncertainty. A report should not jump directly from FASTQ to changed genes; it must first ask whether the observations are complete, correctly labeled, and technically reliable.

Quality profiles, adapter content, read length, GC behavior, duplication, and per-sample read depth all reflect real experimental steps: RNA quality, library construction, fragment selection, sequencer behavior, lane allocation, and possible sample mixing. They are not decorative QC metrics. They define whether downstream statistics can be trusted.

FastQC, fastp, and MultiQC make these risks visible. Adapter contamination can shorten effective reads. Poor-quality tails can affect quantification. A sample with far fewer reads can become sparse. A sample with a distinct quality profile can separate in PCA for technical reasons rather than biology.

The first questions should therefore be: did all expected samples enter analysis, are read counts in a comparable range, was trimming reasonable, and is one sample technically unlike its biological replicates? If QC already looks unstable, DE and enrichment should be treated as exploratory evidence.

### Quantification: Abundance Is an Estimate

Expression quantification turns reads into transcript and gene abundance estimates. It is not direct molecule counting. Ambiguous fragments, similar isoforms, transcript length, effective length, library size, and model assumptions all influence the final counts and TPM values.

Biologically, transcript-level quantification is useful because one gene can produce multiple isoforms. For routine project reporting, however, gene-level matrices are often more stable and easier to connect to annotation, DE, and enrichment. `tximport` and `tx2gene` define how transcript evidence becomes gene evidence.

Counts, TPM, and normalized counts should not be treated as interchangeable units. Counts are closer to statistical evidence for DE modeling. TPM is better for abundance display and expression-profile descriptions. Normalized counts are useful for plots and sample comparison under the model. A high-TPM gene is not automatically differentially expressed, and a significant DE gene is not necessarily one of the highest expressed genes.

When reading quantification outputs, check whether every sample has a quant file, whether matrices contain the expected columns, whether `tx2gene` caused substantial ID loss, whether expression distributions are comparable, and whether low-expression genes were filtered before DE.

### Alignment Branch: Genome-Aware Evidence

The lightweight expression route can answer many expression questions, but genome-aware alignment adds a different layer of evidence. BAM files preserve genomic coordinates, splice junction behavior, strandedness, coverage shape, and mapping quality in a way transcript quantification summaries cannot.

Biologically, the alignment branch helps answer questions closer to genome structure. Do reads support expected exon and intron structure? Is there strong 3 prime or 5 prime bias? Is gene body coverage reasonable? Does strandness match the library protocol? Do many reads fall outside annotation or into multimapping regions?

This branch is optional because it costs more time and storage. Its value is not that it replaces expression quantification, but that it adds auditable coordinate-level evidence for formal delivery, quality review, unusual-sample diagnosis, annotation compatibility checks, and count-based evidence.

If alignment summaries, RSeQC, or Qualimap metrics look unusual, interpretation should return to library type, reference version, annotation format, read length, strandness, and sample origin. A low mapping rate does not automatically mean a failed sample, but it must be explained.

### Counting: Reads Meet Annotation

Feature counting asks which aligned fragments overlap annotated features under the selected rules. The result depends on feature type, `gene_id` attributes, overlap policy, multimapping behavior, strand settings, and how ambiguous reads are handled.

Biologically, a gene-level count matrix is a summary of transcriptional evidence captured by the current annotation. It is not a complete description of all transcription. Novel isoforms, antisense transcription, unannotated loci, repetitive regions, and overlapping genes may be simplified, merged, or lost depending on the annotation and counting policy.

Assignment summaries are one of the most important QC outputs at this layer. A low assigned-fragment fraction may indicate reference mismatch, wrong strandedness, old annotation, contamination, unusual rRNA/noncoding RNA content, or a library type that does not fit the counting model.

The featureCounts matrix can be used as DE evidence and can also be compared with Salmon gene counts. The two sources are produced by different models, so values do not need to match one by one. The stronger question is whether they support the same sample-level structure and major biological signal.

### Differential Expression: Variation Becomes a Model

Differential expression is not simply sample A minus sample B. It places an expression matrix into an experimental design and estimates within-condition variability and between-condition signal. Models such as DESeq2 estimate dispersion, mean expression, fold change, and statistical significance for each gene.

Biologically, the comparison is condition-level, not sample-level. Biological replicates estimate natural variability. A contrast defines the exact question. A design formula defines which factors the model considers. With one condition, condition-level DE is not possible. With a perfectly confounded batch, the model may not separate technical and biological effects.

Read DE plots in two layers. PCA, sample correlation, and expression distributions ask whether the samples and model assumptions look plausible. Volcano, MA, DEG counts, heatmap, and top-gene expression plots show the actual contrast signal. A convincing DE result should make sense at both layers.

Significance and effect size must be read together. Low `padj` means strong statistical evidence under model assumptions. Large `log2FC` means a large estimated change. Both need expression level, sample consistency, gene function, and experimental context before they become a biological story.

### Enrichment: Gene Lists Become Biological Hypotheses

Enrichment analysis changes the unit of interpretation from individual genes to gene sets, pathways, or GO terms. This is useful because many biological processes move as coordinated programs: stress response, ribosome biogenesis, cell cycle, transport, metabolism, signaling, or development.

ORA starts from a thresholded significant-gene list and asks whether a gene set has more hits than expected in the selected background. It is intuitive and useful for reporting strong signals, but it is sensitive to the significance threshold and background universe. GSEA starts from a full ranked list and asks whether gene-set members accumulate at one end of the ranking; it can detect coordinated small shifts.

The most common mistake is treating a term name as a proven mechanism. Enrichment indicates a statistical relationship between current gene evidence and a predefined gene-set definition. Interpretation still needs the actual hit genes, term hierarchy, redundant terms, up/down direction, NES direction, and literature context.

For ORA, the background universe should match the genes that had a real opportunity to be tested. For GSEA, the ranking statistic must be stable and directionally meaningful. If ID loss is severe or the GMT source does not match the organism and annotation version, enrichment can look polished but remain unreliable.

### Report and Provenance: Reproducibility Is Evidence

A final RNA-seq report is not only a collection of figures. It is a deliverable evidence package that should record inputs, upstream flows, tool versions, plot origins, collected tables, methods, and command provenance.

`rnaseq-report-flow` keeps `versions.tsv`, `commands.sh`, `methods.txt`, `plot_gallery.tsv`, `html_reports.tsv`, `tool_links.tsv`, and `run.manifest.json` so the HTML can be read by people and audited by scripts.

Reproducibility does not create biological truth by itself, but it makes disagreements traceable. When a collaborator asks why a term appeared, why a gene disappeared, which step produced a plot, or whether the alignment branch was included, the report should point to concrete files and methods instead of relying on memory.

### Long-Form Chapter Reading Structure

`report_interpretation.html` expands each module into a longer guide chapter. A useful reading structure is:

- Wet-lab origin: which experimental facts this step inherits, such as RNA quality, library type, sequencing depth, sample labels, condition, and batch.
- Biological meaning: which biological question becomes analyzable, such as abundance, genomic coordinates, condition effect, or affected biological process.
- Biological difficulty: which real-system complexities matter, such as isoforms, repetitive regions, sample heterogeneity, cell composition, GO-term redundancy, and gene-ID drift.
- Technical difficulty: which computational choices can change the result, such as reference release, tx2gene mapping, strandedness, feature-counting rules, normalization, design formula, contrast, and background universe.
- Flow implementation: which TAFFISH RNA-seq modules and files preserve the evidence, such as `reference_summary.tsv`, `quant_files.tsv`, BAM/featureCounts/RSeQC/Qualimap outputs, DESeq2 tables, ORA/GSEA tables, and `run.manifest.json`.
- Report interpretation: which figures and tables should be read first, which results can support conclusions, and which results are only hypotheses for follow-up validation.

The purpose is to turn the automatic report from a file index into an interpretation map. It still does not write project-specific conclusions for the user, but it helps beginners understand why each step exists, which wet-lab facts it inherits, which auditable evidence it creates, and how strong a biological claim it can support.

## 6. Statistical Concepts

### Count

A count is fragment support for a gene or transcript. Counts are useful for statistical modeling, but sample-level counts are affected by library size, and between-gene counts are affected by feature length and quantification model.

### TPM

TPM is an abundance measure normalized for transcript length and sequencing depth. It is useful for expression display and abundance trends. Many DE models still prefer count-like evidence rather than testing TPM directly.

### Normalized Count

A normalized count is a count adjusted by sample-level scaling factors so samples become more comparable under the selected statistical model. It is often used for PCA, heatmaps, and top-gene expression plots.

### log2 Fold Change

log2FC describes direction and magnitude of expression change between contrast groups. `log2FC = 1` is approximately two-fold up-regulation, and `log2FC = -1` is approximately two-fold down-regulation. Effect size and significance should be read together.

### p-value and Adjusted p-value

A p-value is evidence against the null model for one test. RNA-seq tests thousands of genes, so multiple-testing correction is required. `padj` or FDR is more appropriate for selecting significant genes.

### FDR

FDR means false discovery rate. It controls the expected proportion of false discoveries under model assumptions. It is not biological validation and does not guarantee that one specific gene is true positive.

### PCA

PCA compresses a high-dimensional expression matrix into a small number of principal components. It is useful for group structure, batch effects, and outliers, but each axis is not an individual gene.

### NES

NES is the GSEA normalized enrichment score. The sign indicates direction, and the magnitude summarizes standardized gene-set level enrichment.

## 7. How to Read Common Figures

### PCA

PCA shows major sample-level variation in a low-dimensional space. Biological replicates should usually cluster together, and conditions may separate along major components. If samples separate by batch rather than condition, check metadata and design.

### Sample Correlation Heatmap

The sample correlation heatmap helps assess replicate consistency and possible outliers. Low within-group correlation or one sample that is unlike all others should trigger checks of QC, labels, and lab records.

### Expression Distribution

Expression distribution plots show whether samples are comparable after filtering and normalization. Strong shifts may reflect sequencing depth, library quality, normalization, filtering choices, or true sample differences.

### Volcano Plot

The volcano plot combines effect size and statistical significance. The x-axis is usually log2FC, and the y-axis is usually `-log10(padj)`. Upper left and upper right genes are often prioritized, but plot position alone does not prove mechanism.

### MA Plot

The MA plot shows average expression versus log2FC. It helps reveal whether low-expression genes are overly variable and whether fold-change shrinkage behaves reasonably.

### DEG Count Barplot

The DEG count barplot summarizes up- and down-regulated gene counts at the chosen threshold. It is useful for overview reporting but does not replace gene-level table review.

### Heatmap and Top-Gene Expression

These plots show representative expression patterns. Genes are selected and colors are usually scaled, so they are best for pattern inspection rather than absolute-expression claims.

### ORA Dotplot and Barplot

ORA plots show which gene sets contain more significant genes than expected. Dot size often represents hit count, and color often represents adjusted p-value. Interpret them together with the background universe, gene-set source, and hit genes.

### GSEA NES Plot and Enrichment Curves

The NES plot shows normalized enrichment score and direction. Running enrichment curves show where members of representative gene sets accumulate along the ranked gene list. GSEA is useful because it does not require a hard significant-gene cutoff, but it does require a stable full-gene ranking.

## 8. ORA vs GSEA

ORA usually starts with a significant-gene list. It asks whether a gene set contains more significant genes than expected under the selected background universe. It is simple and intuitive, but sensitive to padj/log2FC thresholds and background definition.

GSEA usually starts with a ranked list of all genes. It asks whether members of a gene set tend to accumulate at one end of the ranking. It does not require a hard significance cutoff and can detect coordinated small shifts.

Therefore, ORA and GSEA are not equivalent. Different results are not necessarily a problem; they often reflect different questions.

## 9. Common Misinterpretations

- A significant DE gene is not automatically a validated biomarker.
- An enriched term is not a proven mechanism.
- Similar GO term names do not mean terms can be merged freely.
- A significant p-value does not necessarily mean a large effect or high biological importance.
- Small sample size, batch confounding, or incomplete metadata make significance harder to interpret.
- An inappropriate background universe can bias ORA.
- Lost or mixed gene IDs can distort enrichment.
- Clean-looking plots do not prove that experimental design is sound.
- Automated report text does not replace experimental context, literature, and validation.

## 10. Beginner FAQ

### Can three WT samples be analyzed with rnaseq-standard-flow?

Yes, for expression matrices, QC, and sample relationship checks. The sample table can contain one condition. In that case, DE/enrichment should be skipped or the expression route should be used alone. A condition-level comparison such as WT versus treatment is not possible without a second condition.

### Why do some genes disappear downstream?

Common reasons include low-count filtering, ID mapping loss, annotation scope, missing `tx2gene`, background filtering, or a tool retaining only genes that can be modeled statistically.

### Why do samples from the same condition not cluster together in PCA?

Possible reasons include sample-quality problems, sample-label mistakes, batch effects, strong true biological heterogeneity, or the selected condition not being the dominant source of variation. Review metadata, QC, lab records, and sample processing.

### Why are enrichment results sometimes broad?

Many GO terms are broad by design. Broad terms are especially common with large gene lists or weak background definitions. Interpret them with hit genes, term hierarchy, GSEA direction, and literature context.

### Does report-flow recompute results?

No. `rnaseq-report-flow` is a static collector. It collects upstream tables, plots, HTML reports, versions, commands, and methods, then renders a project-level report and interpretation companion page.

## 12. Interpretation Boundary

`rnaseq-report-flow` is a static collector and interpretation aid. It does not rerun upstream analysis, modify upstream outputs, or make final biological conclusions. Formal project delivery should combine this report with experimental design, sample metadata, organism context, prior literature, and domain expert review.
